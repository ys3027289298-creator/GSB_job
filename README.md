# 桥梁应急检修

这是 YS_01 的初始环境说明。当前仓库只提供规则口径和样例数据，不提供页面实现。最终项目需要在浏览器中离线运行，不依赖后端服务。

## 运行口径

- 一个班次为 480 个模拟分钟，默认按 1 分钟推进。
- 桥面共有 3 条车道：L1、L2、L3。车道可以关闭、开放或设置为施工缓行。
- 每个检修任务必须满足前置任务、人员技能、设备占用和车道安全条件后才能开始。
- 同一名队员、同一台设备和同一条车道不能被两个活动同时占用。
- 交通压力会随模拟时间和关闭车道数量变化；压力过高会增加事故风险。
- 施工区没有完成隔离时，不能执行需要封道的任务；在不满足安全条件时强行施工会产生事故记录。
- 已经发生的事故、检测结果和已完成的时间不能通过撤销操作回滚。
- 玩家可以暂停、单步推进和重新安排尚未执行的调度。
- 随机事件必须由固定种子驱动，同一初始状态和种子应产生相同的事件顺序。

## 初始数据

`samples/bridge-scenario.json` 是一份可运行的示例场景，包含车道、检修点、人员、设备、任务、交通曲线和随机种子。实现时可以扩展数据结构，但不能改变样例字段的含义。

## 需要保留的可验证行为

- 任务前置关系和资源占用检查。
- 车道关闭、施工隔离和交通压力计算。
- 事故风险和班次结算。
- 未执行调度的撤销，以及已发生事件不可撤销。
- 刷新后的存档恢复和存档版本校验。
- 操作日志能够指出模拟时间、操作者、对象、动作和结果。
